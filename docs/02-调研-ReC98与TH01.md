## 2. 二进制结构

TH01 原始运行链：

```
ZUNSOFT.COM   logo（TINY）
OP.EXE        标题/菜单（LARGE）
REIIDEN.EXE   地狱路线（LARGE，BINARY == 'M'）
FUUIN.EXE     封印/魔界路线（LARGE，BINARY == 'E'）
GAME.BAT      先 mdrv98 -M7 → zunsoft → op → mdrv98 -R
MDRV98.COM    MDRV2 音乐 TSR（INT F2h）
```

`debloated` 把前三个 EXE 合并成多入口单二进制：

- `th01/pc98/entry.cpp` / `entry.hpp`：
  - `main_setup`（复刻 GAME.BAT：resident + MDRV2 spawn + zunsoft + op）
  - `main_op`
  - `main_main`（REIIDEN/FUUIN）
  - `main_cutscene`
  - `entrypoint_exec()` 用 `execl()` 重启自身并传入口名。
- `th01/pc98/game_bat.cpp`：resident / MDRV2 加载/移除。
- `th01/pc98/blitters.cpp`：TH01 专用快速 blitter。
- `resident.hpp`：`resident_get()` / `resident_get_or_create()`，不再到处 `__seg`。
- `main_01.cpp` / `op_01.cpp`：清理 `pascal`、段声明、部分 bloat。

**对 Android 的意义**：不用 `exec` 三个 EXE，直接进程内切 `main_op` / `main_main`；`resident_t` 改成全局结构体；MDRV2 调用换成音频后端。

## 3. 代码里的 16 位残留

### 3.1 `platform.h` 直接拒绝非 Borland

根 `platform.h`：

```c
#if defined(__TURBOC__) && defined(__MSDOS__)
typedef unsigned char bool;
typedef int bool16;
typedef int int16_t;
...
#else
#error This code can currently only be compiled on Borland's 16-bit DOS compilers.
#endif
```

这是移植的第一道门：先写 Android/clang 版本的 `platform.h`。

### 3.2 `x86real.h`

提供：

- `__emit__` / `__int__` / `disable()` / `enable()` / `geninterrupt()`；
- `inport/outport`；
- `REGS` / `SREGS` / `int86` / `getvect/setvect`；
- `MK_FP` / `FP_SEG` / `FP_OFF` / `peek/poke`；
- `_AX/_BX/...` 伪寄存器；
- `intvector_segment()`。

Android 版本：

- I/O 端口：空实现或映射到软件视频寄存器；
- `int86`：只保留需要的 BIOS 调用（GDC/键盘/时间），改成回调；
- `peek/poke`：段表 + 平面内存；
- 伪寄存器：删掉，相关代码改普通 C++。

### 3.3 `planar.h`

- `VRAM_PLANE[4]` 是 `dots8_t far *`，指向段 `0xA800/0xB000/0xB800/0xE000`；
- `VRAM_OFFSET_SHIFT(x,y)` 假设 80 字节/行、4 平面；
- `VRAM_CHUNK` 是 far 指针算术；
- `vram_segment()` / `grcg_segment()` 把坐标转成 x86 段；
- EGC/GRCG 宏直接用 `peekb/pokeb`。

Android 版本：

- 4 个平面各 32,000 字节的 flat 数组（2 页 = 2 组）；
- `VRAM_PLANE_*` 指向当前页的平面；
- `VRAM_CHUNK` 改成普通指针/引用；
- `vram_segment`/`grcg_segment` 改成 `plane_base + offset`；
- `peek/poke(SEG_PLANE_*, off)` 映射到 `plane_base[off]`。

### 3.4 `resident_t`

`th01/resident.hpp`：

```c
struct resident_t {
    char id[sizeof(RES_ID)];
    int8_t rank;
    bgm_mode_t bgm_mode;
    ...
    unsigned long rand;
    score_t score;
    ...
    uint16_t continues_per_scene[SCENE_COUNT];
    ...
    unsigned int stage_id;
    unsigned long hiscore;
    ...
};
extern resident_t __seg *resident;
```

- `__seg*` 是 DOS 段指针；Android 改 `resident_t*` 指向静态全局。
- `int8_t/uint16_t/uint32_t` 已经固定；但 `enum` 宽度、`bool16`、`unsigned int` 仍需检查。
- `ResData<T>` 用 `((sizeof(T)+0xF)>>4)` 算段落数；Android 不需要。
- `resident_create_and_stuff_set` / `resident_stuff_get` 用 `resdata_create/exist`；改成单例。

### 3.7 源文件编码

`th01/shiftjis/fns.hpp` 是 **CP932**：

```c
#define ARC_FN "東方靈異.伝"   // 实际字节 93 8C 95 FB E8 CB 88 D9 2E 93 60
```

NDK clang 实测可以编译 CP932 字符串（只报 `-Winvalid-source-encoding` 警告），
加 `-Wno-invalid-source-encoding` 即可。**不要整体转 UTF-8**，否则游戏内文本字节会变，
`_mbcjmstojis` / `text_putsa` 会错。


### 4.2 `.GRP`（Pi “ZN”）

`ST0.GRP` 头：

```
5A 4E 1A 00 00 00 00 04 50 43 39 38 00 00 02 80 01 90 ...
Z  N  ^  header...
```

| 偏移 | 值 | 含义 |
| --- | --- | --- |
| 0x00 | `"ZN"` | 魔数（Pi 变体） |
| 0x02 | `0x1A` | 注释结束 |
| 0x03 | 00 | header start |
| 0x04 | 00 | mode |
| 0x05 | 04 | aspect X |
| 0x06 | 00 | aspect Y |
| 0x07 | 04 | bitdepth（4bpp） |
| 0x08 | `"PC98"` | compressor model |
| 0x0C | 00 00 | compressor data size |
| 0x0E | 02 80 | width = 640（大端） |
| 0x10 | 01 90 | height = 400（大端） |
| 0x12 | 48 字节 | palette（16 × RGB，每分量 4-bit 值） |
| 0x42 | ... | 压缩流 |

解压算法（见 <https://mooncore.eu/bunny/txt/pi-pic.htm>）：

- delta table：`16×16`，初始化 `table[a][b] = (16 + a - b) % 16`；
- delta 码变长：`1x`→0-1，`00x`→2-3，`010xx`→4-7，`011xxx`→8-15；
- 重复命令：`00` 重复上 2/4 字节、`01` 上一行、`10` 上两行、`110` 上一行+1、`111` 上一行-1；
- 重复长度也是变长；
- 先两个 delta，再一个重复序列（首个长度 -2），然后循环；
- 输出 640×400 索引，再按 4 平面展开。

### 4.3 `.GRZ`

`BOSS8.GRZ`：

```
48 47 52 5A 10 00 00 00 00 01 00 00 92 05 00 00 ...
H  G  R  Z  image_count=16 ...
```

- `"HGRZ"` + `image_count` + 16 个 `int32` offset + `total_size` + 20 字节 unknown。
- 每个 image 是 `"HGRX"`：header + palette + RLE stream + planar stream。
- `th01/formats/grz.cpp` 有完整解码/显示逻辑，可直接搬。

### 4.4 `.GRF`

`MASK.GRF`：

```
48 47 52 46 01 0A 20 20 75 0A 75 0A ...
H  G  R  F ...
```

- `"HGRF"`，单平面 RLE；HUD 只读第一平面。
- `th01/formats/grf.hpp` 有说明；`grf.cpp` 实现。

### 4.5 `.BOS` / `.PTN` / `.PF`

- `.BOS`：`"BOSS"` + `vram_w` + `h` + `spriteformat_header_inner_t` + palette + 5 平面（B/R/G/E/alpha），任意尺寸。
- `.PTN`：`"HPTN"` + `unused` + `image_count` + palette + N × (1 字节 + 4 × 32×32 平面)；alpha = `~(B & R & G & E)`（颜色 15 透明）。
- `.PF`：64 × 32 字节头；文件名逐字节 XOR `0xFF`；压缩类型 `0x95 0x95`（“封”）是 RLE，`0x88 0xF3` 等是原样；`ARC_KEY = 0x76`；`arc_file_seek` 只支持 `int8_t`。
- 归档 `東方靈異.伝`（298,073 字节，41 项）：

```

BOSS1.BOS … BOSS8_E2.BOS
MIKO_AC.BOS / MIKO_AC2.BOS
BOSS5_GR.GRC / BOSS6GR1-4.GRC / KUZI1-2.GRC
BOSS3_M.PTN / MIKO.PTN / NUMB.PTN / STG.PTN / STG_B.PTN / TAMAYEN.PTN
```

### 4.6 `.BFNT`

`TOUHOU.DAT`：

```
42 46 4E 54 1A 83 16 00 40 00 10 00 00 00 0F 00 5A 55 4E 4F ...
B  F  N  T ...
```

### 4.7 `.MDT` / `.MDE` / `MDRV98.COM`

- `MDRV98.COM` 字符串：

```
MDRV2 ver 3.4F for  PC-98 Series  94/01/30
Copyright (c) 1989-94 Regulus / NARIMI.A  Rel.2.31
```

- `INT 0xF2`，功能号 `MSET/MPLAY/MSTOP/MFADE_*`；BGM `.MDT`，SE `.MDE`。
- `.MDT` 头：

```
02 03 0D 00 01 00 | e8 00 | 80 00 | fe 00 | 81 00 | ...
```

  看起来是版本/轨道偏移表；`0x40` 之后是 Shift-JIS 标题 + 命令流（`e9/ea/eb/ec/ed/e6/e7` 等）。
- TH01 的 19 个 `.MDT` 文件：`init`、`reimu`、`positive`、`legend`、`kami`、`kami2`、`zipangu`、`st0`–`st6`、`alice`、`tensi`、`syugen`、`shugen`、`iris`。`MUSIC_FILES` 在音乐测试里列 15 首；`init/kami2/shugen/st6/syugen` 等用于其他场景或为重复/变体。
- 没有现成 MDRV2→MIDI/OGG 转换器；日文资料建议“模拟器播放 + 录音”。
- `MDRV98.COM` 是第三方 TSR，不能进公开仓库/APK。

## 5. master.lib 的规模

- `libs/master.lib/` 有 **230 个 `.asm`**（含 data/bss），是 16 位汇编库。
- TH01 的三个 `.asm` 入口显式 include 了 **51 个**模块（见 PLAN §4.5）。
- 链接器还会从 `bin/masters.lib` 拉进被引用的函数（`super_*`、`grcg_circlefill`、`graph_pi_load_pack` 等）。
- 估算实际要实现 **60–80 个入口**；不要按 230 个估。

分类：

| 类别 | 代表函数 | Android 实现 |
| --- | --- | --- |
| 文件 | `file_ropen/read/seek/close/create/write/exist`、`dos_*` | `FILE*` / `std::filesystem` |
| 内存 | `mem_assign*`、`hmem_*`、`smem_*`、`resdata_*`、`respal_*` | `malloc` / 全局单例 |
| 输入 | `key_start/end/sense/beep`、`keybios` | 输入状态 + Java/SDL 事件 |
| 图形 | `graph_start/clear/show/hide/400line/copy_page/scrollup`、`graph_pi_load_pack` | 平面 VRAM + 解码器 |
| 调色板 | `palette_init/show/settone/black/white` | 16 色数组 + 软件 fade |
| GRCG | `grcg_setcolor/settile/pset/fill/line/circle/box/polygon/trapezoid` | 软件填充/画线 |
| EGC | `egc_on/off/start`、`egc_shift_*`、`egc_copy_rect_*` | 软件 blit |
| 文本 | `text_clear/fillca/putca/puts/putsa`、`gaiji_*` | TRAM + FreeType |

| 音频 | `bgm_*`（beep） | 可先忽略/简单方波 |

## 6. 结论

- **游戏逻辑可复用度很高**：纯玩法 ~19k 行，依赖的是有限的平台 API。
- **工作量集中在平台层**：平面 VRAM + EGC/GRCG + 文本/字体 + master.lib 子集 + MDRV2。
- **不要重写玩法**；用 ReC98 `debloated` 的多入口结构，替换平台层。
- **先做图形/输入/Stage 1**，音频和全路线后置。
